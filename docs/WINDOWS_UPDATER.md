# Обновление Windows bundle

Updater впервые включён в desktop `2.1.12`. Опубликованный `2.1.11` не содержит
этой функции: первую сборку 2.1.12 нужно установить вручную целиком.

## Пользовательский flow

В «Настройках» показаны версия GUI из встроенного `wails.json`, версия bundled core с проверкой SHA-256 по встроенному `core_identity.json` и совместимость с нашим сервером.
При открытии приложения выполняется одна автоматическая проверка. Кнопка
«Проверить обновления» повторяет её вручную. Linux не предлагает установку.

После проверки показаны версия, требования к серверу и release notes обычным
текстом. Только нажатие «Скачать, установить и перезапустить» начинает установку.
Профили, `config.json` и `device-id` в `%AppData%\csqtt` не перемещаются и не удаляются.
Текущие поля настроек сохраняются перед установкой. VPN после перезапуска
автоматически не подключается.

Загрузка показывает progress и допускает отмену. Оборванный/повреждённый ZIP
удаляется; следующая попытка начинает загрузку заново. Ошибка GitHub/проверки
целостности не останавливает действующий VPN. После проверки файлов приложение
запрещает новые подключения, отменяет Connect, ждёт его окончания, снимает
маршруты/DNS/NRPT и ждёт завершения core. Не подтверждённая очистка запрещает
установку. Позднее добавление bypass из лога core блокируется при shutdown.

GUI содержит `requireAdministrator`; helper наследует повышенный token.
Если приложение запущено без Administrator, установка выдаёт ошибку с просьбой
перезапустить GUI через UAC. Helper не запрашивает отдельные credentials.
Обновляется только приложение с именем `CSQTT-VPN.exe` и каталогом `bin`.
Нужны Windows 10/11 x64, WebView2 и место для ZIP, распаковки и backup.
Junction/reparse point в пути установки запрещён.

## Источник и контракт release

Единственный источник: `https://api.github.com/repos/danusha2345/csqtt-vpn/releases/latest`.
Используется только стабильный `vMAJOR.MINOR.PATCH`, строго новее GUI.
Draft/prerelease, downgrade, дубликаты assets, неизвестная архитектура и
отсутствие метаданных блокируют установку.

Обязательные assets для версии `X.Y.Z`:

- `CSQTT-VPN-X.Y.Z-windows-amd64.zip`, не больше 256 MiB;
- `BUILDINFO-X.Y.Z.json`, не больше 1 MiB;
- SHA-256 обоих assets в поле `digest` ответа GitHub Releases API.

`BUILDINFO.version` должен совпадать с tag, `sha256[имя ZIP]` — с digest ZIP,
`compatibility.serverFork` — с `danusha2345/csqtt-android`;
`compatibility.socks5` содержит непустое описание требований к серверу.
Метаданные также скачиваются с проверкой размера и digest.
`SHA256SUMS-desktop-X.Y.Z.txt` остаётся полезным для ручной установки, но updater
не использует его как обход отсутствующего GitHub digest.

URL assets строятся кодом из фиксированных имён, а не принимаются из UI,
release body или `browser_download_url`. HTTPS redirects допускаются только
для `github.com`, `api.github.com`, `release-assets.githubusercontent.com`,
не больше пяти; userinfo и нестандартные ports запрещены.
Это проверка целостности относительно доверенного GitHub API нашего репозитория,
не отдельная цифровая подпись издателя.

Live-проверка 2026-09-08: опубликованный `v2.1.11` соответствует контракту.
Windows ZIP: 9 571 366 байт,
SHA-256 `335ee12702c75e1645e080b3b6a8bb9288625d3170ef98e7b72beae7f7844d56`.
Новый код успешно выполнил check, download, hash, extraction и PE validation
этого настоящего release (с тестовым current=`2.1.10`, без запуска EXE).

ZIP допускает только:

```text
CSQTT-VPN.exe            # обязательно, PE amd64 executable
bin/csqtt-client.exe     # обязательно, PE amd64 executable
wintun.dll              # обязательно, PE amd64 DLL
bin/                    # необязательная directory entry
README.txt              # необязательно
LICENSE                 # необязательно
```

Точное сравнение имён запрещает traversal, ADS, UNC/drive paths, backslash,
case aliases, дополнительные DLL/EXE и symlinks. Дубликаты запрещены.
Суммарная распаковка ограничена 512 MiB, один файл — 256 MiB.
Будущие изменения формата ZIP требуют явного изменения allowlist и тестов.

## Helper, замена и восстановление

Helper — копия текущего GUI, запущенная с внутренним аргументом до инициализации
Wails. Дополнительный release asset для helper не нужен. Каталог
`.csqtt-update-<random>` внутри установки создаётся сразу с owner Administrators
и защищённой DACL (Administrators/SYSTEM). ZIP, ticket и helper не доступны
для записи обычным пользовательским процессом. Установленные файлы получают
чтение/исполнение для Users, запись — Administrators/SYSTEM; это необходимо
для запуска из Explorer с последующим UAC.

Helper проверяет путь процесса по открытому handle исходного PID, checksum ZIP,
PE и захватывает mutex установки. Затем сигнализирует `ready` и ждёт завершения
именно этого процесса (60 секунд). GUI выходит только после `ready`.
Перед первой заменой сохраняются все старые файлы в `backup/` и синхронизируется
`transaction.json`. Все три бинарных компонента заменяются вместе с optional
README/LICENSE; другие файлы установки не затрагиваются.

Занятые файлы получают ограниченные повторные попытки rename. Ошибка любой
замены вызывает восстановление **всех** старых файлов. Backup при rollback
копируется, не расходуется. При успехе замены helper запускает новый GUI и ждёт
60 секунд подтверждения от готового frontend с ожидаемой версией. Падение,
ошибка CreateProcess или отсутствие подтверждения приводят к остановке нового
процесса, rollback и запуску предыдущей версии. Подтверждение frontend не является
проверкой TURN/Wintun/сервера.

Ошибка helper сохраняется в `error.txt` и показывается в настройках при следующем
запуске. Если невозможно остановить новый процесс или восстановить заблокированный
файл, helper сохраняет backup и явно пишет ошибку; успешный rollback не заявляется.
При успехе большие временные файлы удаляются; небольшой каталог с helper и
журналом остаётся. После закрытия приложения его можно удалить вручную.

При отключении питания/принудительном убийстве helper во время замены нет
автоматического восстановления после reboot. Для ручного восстановления:
закрыть GUI/core/helper, открыть каталог установки с Administrator, по
`transaction.json` восстановить файлы из `backup/` с теми же относительными путями,
удалить только добавленные файлы с `Existing=false`, затем запустить GUI.
До восстановления не удалять каталог транзакции. Обычные ошибки операций и
неудачный запуск обрабатываются автоматическим rollback.

## Проверки и release gate

В Linux выполнены unit/race/vet, тесты отказов на каждом шаге замены,
повторяемого rollback, сохранности постороннего файла, отмены/обрыва/подмены
загрузки, ошибок metadata, ZIP traversal/symlink/duplicates/missing/не-PE.
Выполнены Windows amd64 cross-compilation GUI, core tests и updater tests,
Windows vet, npm audit/build. Playwright проверяет UI с имитацией Wails bindings;
это отдельная проверка браузерной части, не Windows runtime.

В Windows CI выполнены нативные тесты блокировки файлов, rollback и DACL stage.
Полный GUI runtime, UAC, WebView2 restart и TUN/VK E2E на рабочем ПК
**не проверены**; эти сценарии остаются в матрице ниже.

Матрица проверки на Windows 10/11 (не заменяется cross-compilation):

1. Запустить `go test ./updater -v` из повышенного терминала: включая настоящий
   `CreateFile` lock/rollback и DACL/owner тест. Запустить `go test ./core`.
2. Проверить UAC, путь с пробелами/кириллицей, отсутствие прав записи, два GUI,
   второй updater и временную блокировку EXE/DLL антивирусом.
3. Обновить тестовую старую сборку с активным VPN: проверить отсутствие split
   routes, managed NRPT, bypass и старого core перед заменой; сравнить настройки,
   профили и `device-id` до/после.
4. Проверить потерю сети/отмену, повреждённый ZIP, отказ rename, падение нового GUI
   и timeout frontend; убедиться в rollback и наличии диагностического журнала.
5. Проверить реальный WebView2 restart, версии GUI/core, затем отдельно TURN E2E
   с совместимым сервером. Не объявлять E2E по факту готовности frontend.
6. Для release повысить `wails.json`/Windows version resources, проверить фактическую
   версию bundled core, актуализировать текст совместимости в `VersionInfo`,
   опубликовать точный контракт assets/BUILDINFO и сначала проверить его read-only.

В 2.1.12 updater объединён с оптимизациями из [WINDOWS_PERFORMANCE.md](WINDOWS_PERFORMANCE.md).
